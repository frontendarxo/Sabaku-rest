# Sabaku — сайт на Next.js

Next.js 15 (App Router) + TypeScript. Страница статическая (SSG), JS на первую загрузку ~107 КБ.

## Запуск

```bash
npm install
npm run dev        # http://localhost:3000
npm run build && npm start
```

Деплой: Vercel (подключить репозиторий) — кэш-заголовки из `next.config.ts` применятся автоматически.
Для OG-картинок задайте `NEXT_PUBLIC_SITE_URL` (например `https://sabaku.ae`).

```

  ScrollFilm.tsx    фильм по скроллу на canvas (фасад → норэн → зал → стол)
  LiveDish.tsx      главы с видео-петлями блюд
  MenuBoard.tsx     меню-доска с вкладками
  Nav.tsx           шапка (белая поверх фильма, тёмная после)
lib/
  film.ts           наборы кадров, фокус-трек, безопасные зоны
  frameLoader.ts    приоритетный загрузчик кадров
  menu.ts           меню, цены, тексты, адрес
public/media/film2/
  hd/  1920px (317 кадров) — мониторы от 1800px
  sd/  1280px — ноутбуки, планшеты горизонтально, медленный интернет
  m/   720×1088 вертикальный, с «операторской» панорамой по блюдам — телефоны

assets/interior/              фото интерьера для блоков (через next/image)
scripts/make-frame-sets.mjs   пересобрать sd из hd (npm run frames)
```

## Фильм

Снят из 4K-источника (Kling 3.0 4K), три сцены одним планом:
1. подходим к фасаду SABAKU и проходим сквозь норэн;
2. идём по залу мимо сада камней и садимся за стол;
3. официант по очереди ставит Fluffy Pancakes, Sabaku Matcha и Sencha — подписи с ценой появляются в момент подачи (`CAPTIONS` в `lib/film.ts`).

## Как решена долгая загрузка

1. **Мгновенный первый экран.** Первый кадр — обычная картинка `<picture>` с `fetchPriority="high"` и `<link rel="preload">` под нужный экран; она видна, пока canvas не получил кадр.
2. **Каждое устройство качает только свой набор.** Телефон ≈ 13 МБ (`film2/m`), ноутбук ≈ 18 МБ (`film2/sd`), монитор от 1800px ≈ 30 МБ (`film2/hd`) — грузятся по приоритету, фильм листается почти сразу. Раньше любой экран грузил всё.
3. **Приоритетная очередь кадров** (`lib/frameLoader.ts`): сначала первые 12 кадров, затем кадры вокруг текущей позиции скролла (с упором вперёд), затем остальные «от грубого к точному» (каждый 8-й, 4-й, 2-й…). При быстром скролле никогда нет пустого экрана — показывается ближайший загруженный кадр.
4. **Не больше 6 запросов одновременно** и декодирование вне главного потока (`createImageBitmap`) — скролл не дёргается.
5. **Медленный интернет / Save-Data** → набор 960px и каждый 2-й кадр (вдвое меньше трафика).
6. **Видео блюд** не грузятся заранее (`preload="none"` + постер), подключаются за экран до появления и играют только когда видны.
7. **Кэш на год** для `/media/*` (`Cache-Control: immutable`) — повторный визит мгновенный.
8. Шрифты локальные (без запросов к Google), арабский шрифт грузит только арабские глифы.

## Как решено одинаковое отображение на всех экранах

- **Два кадрирования фильма**: горизонтальное для широких экранов и вертикальное для телефонов/планшетов (выбор по пропорции экрана, не по ширине). В вертикальном наборе камера плавно «переводит взгляд» на каждое блюдо в момент подачи.
- **Фокус-трек** (`FOCAL_TRACK` в `lib/film.ts`): кадр центрируется на главном объекте — сначала вывеска и дверь, потом зал, потом стол с блюдами. Точка плавно интерполируется между ключами.
- **Безопасная зона** (`safeW` / `safeH`): если «cover» обрезал бы больше допустимого (мониторы 21:9 и шире, узкие складные телефоны), кадр чуть уменьшается, а края заполняются размытой копией того же кадра — главный объект никогда не обрезается.
- **Видео блюд** — фиксированный квадрат 1:1 + `object-fit: cover`: одинаковая композиция везде.

## Что заменить перед запуском

- Цены в `lib/menu.ts` (сняты с доски меню, фото ноябрь 2024) — сверить с рестораном.
- Рамен подписан как сезонный — уточнить у ресторана.
- Новый фильм: положите кадры `f_000.webp…` в `public/media/film2/hd` и `film2/m`, затем `npm run frames`. Если кадров другое число — поменяйте `FRAME_COUNT` и тайминги `CAPTIONS`.
